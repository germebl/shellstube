# Bauplan

Schmal vor breit. Ein durchgehend funktionierender Pfad für **eine** Konfiguration schlägt
einen halbfertigen Katalog für alle.

| | Was | Tor |
|---|---|---|
| **M0** | Repo, Lizenz, Schema-Entwurf, CI mit Prüfern | Ein Fremder versteht in 10 Minuten, was das Projekt ist und wie er beiträgt |
| **M1** | Bauplan-Assistent auf der Website | Erzeugt gültiges YAML gegen das Schema, zehn Beispielpläne sind indexierbar |
| **M2** | Stufe T0 von Ende zu Ende, fünf Dienste | Frische VM → laufendes Homelab → simulierter Totalausfall → vollständige Wiederherstellung, automatisiert |
| **M3** | Dokumentation als Produkt, `llms.txt`, EN-Übersetzung | Kein Dienst ohne Doku-Seite, keine Doku-Seite ohne Code — maschinell geprüft |
| **M4** | Stufe T1, Katalog für Beiträge geöffnet | Ein externer Beitrag läuft ohne Rückfragen durch |
| **M5** | Stufe T2 — Netz als Plan, mehrere Knoten | Netzplan als Diagramm exportierbar, Schritt für Schritt abarbeitbar |
| **M6** | Stufe T3, Betriebsreife | Rückmeldungen aus echten Installationen, nicht aus unserer Vorstellung |

Die Stube (Konto, gespeicherter Plan, Werkzeuge) kommt **nach M2**. Ein Konto, in dem man
einen Plan speichert, den das Werkzeug noch nicht bauen kann, ist ein leeres Regal.
